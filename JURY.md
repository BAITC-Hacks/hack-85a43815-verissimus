# EnergyAI: быстрая проверка для жюри

EnergyAI формирует почасовой прогноз **нормализованной мощности двух турбин на 24–48 часов**. Исторический сценарий фиксирует момент решения, выбирает исходный выпуск NOAA GFS и проверяет, что используемые данные доступны не позже этого момента.

## Проверка без сети, исходных CSV и ключа OpenAI

После установки зависимостей по [README](README.md), из корня проекта:

Здесь `python` — интерпретатор виртуального окружения. Если окружение не активировано, в Windows используйте `.\.venv\Scripts\python.exe`, в Linux/macOS — `.venv/bin/python` вместо `python` во всех командах ниже.

```text
python scripts/verify_submission.py
python -m unittest discover -s tests -q
```

Ожидается `status: success`, `row_count: 1344`, `daily_runs: 56`, `weather_sources_checked: 5376`; проходят 104 теста. Верификатор проверяет согласованность сохранённых материалов, а не точность февральского прогноза.

## Полный сценарий с исходными данными

Поместите CSV организаторов в `data/turbine_1.csv` и `data/turbine_2.csv` согласно README. Запустите:

```text
python -m streamlit run app.py
```

Выберите `turbine_1`, `01.02.2026`, `48` часов; нажмите **«Рассчитать выбранный прогноз»**. Покажите источник и время погодного выпуска, график, **«Проверки прогноза»** и **«Эффект калибровки на последующих январских прогнозах»**. Скачайте HTML-отчёт. Кнопка расчёта работает без ключа OpenAI; для первого получения погоды нужен доступ к архиву NOAA.

При настроенном локальном OpenAI API-ключе чат вызывает расчётные инструменты; журнал показывает их имена, статусы и идентификаторы. [Двухминутная демонстрация](DEMO.md) содержит готовый запрос. [README](README.md) описывает пакетный февраль, автоматическую повторную проверку и воспроизведение обучения калибратора.

## Как интерпретировать результат

На январской проверке с датами начала прогнозов 17–23 января MAE уменьшилась с **0,3221 до 0,2210** после калибровки по более ранним данным. Это относительное снижение ошибки на **31,38%**, не процент точности и не оценка февраля. Перекрывающиеся 48-часовые окна не являются независимыми наблюдениями. На дополнительном январском окне MAE первых суток немного ухудшилась; полное сравнение приведено в README.

Часовой пояс `Asia/Almaty` принят как допущение. База нормализации неизвестна: перевод в МВт, МВт·ч и денежную экономию не выполняется. HTTP Last-Modified служит свидетельством архива, а не независимым журналом первой публикации. Фактическая февральская мощность в предоставленных CSV отсутствует.
